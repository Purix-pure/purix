## 1. What was found and fixed

Every item below was reproduced first, then fixed with a test that failed before the fix.

| Item | Found | Fix |
| --- | --- | --- |
| H3: tool errors reach the model unfiltered | An error thrown inside an MCP tool went back as a protocol error with the raw message, e.g. Node's `ENOENT ... '/home/you/.purix/...'`. Three `catch` sites returned `err.message` directly. | `security/error_text.ts` (`sanitizeErrorText`) and `toolErrorResult` in `mcp-server/src/server.ts`. A throw becomes a normal tool error (`isError`). Project root becomes `<project>`, home becomes `~`, known secret formats and masked key fragments are redacted, stack frames are dropped, length is capped. |
| H3: provider error bodies | Up to 500 characters of a provider's reply were pasted into the error message. Providers echo the key you sent (masked) and sometimes more. | Same sanitizer on the three provider sites in `llm/providers.ts`. Status codes and the useful words are kept (tested for OpenAI-compatible, Anthropic, Gemini). |
| H5: full disk reported as "damaged" | On a real 1 MB filesystem: `status`, `stats`, `lock`, `check` said "the local store is damaged (disk I/O error)" or a bare "disk I/O error"; `index` and `remember` printed a raw `ENOSPC`. | `platform/disk_full.ts`. A full disk is named as such, with the way out. A bare "disk I/O error" counts as a full disk only when the filesystem has under 1 MiB free; corruption messages never do. `check`, `lock`, `audit-log` and the top-level failure line use it. |
| H4: a record from a newer Purix was read as current | An entry with `schema_version: 9` (and an unknown status) was accepted: `purix check` printed a green "Verification status" and `purix lock` wrote it. | `migrateManifestEntry` refuses it with a plain `Error` that names both numbers and says to upgrade. `purix.lock.json` with `schema` above 1 gets the same wording. `check`, `lock` and `audit-log` say "written by a newer Purix", not "damaged". |
| H4: dead-code scan | None existed. | `scripts/measure-unused-exports.mjs` (measurement only, never fails). |
| H7 / A6: files with no named test | The plan says 65. | `scripts/measure-untested-files.mjs`. See section 3. |

Basis for the schema rule: Terraform refuses a state file written by a newer version and names the version to upgrade to ([HashiCorp, "Manage Terraform versions"](https://developer.hashicorp.com/terraform/tutorials/cli/versions)). The provided research folder has no guidance on this; the rule is borrowed from that precedent, not from Purix research.

## 3. Measurements

**A6, files with no named test** (`node scripts/measure-untested-files.mjs`, 255 source files, 373 test files). The plan's "65" is not reproducible, and its definition is not in the repository. Under four readings:
- No sibling test with the same stem (strictest): 75.
- Named by a test (sibling, or a test imports it): 216.
- Started by a test as a worker, by file name: 17.
- No test names it: 20, of which 17 are imported by a tested file and 3 by nothing.

Largest of the 20: `tools/catalog_data.ts` (295 lines), `gates/manifest_delta.ts` (160), `cli/commands/lang.ts` (149), `cli/commands/change.ts` (138), `verify/config_value.ts` (113). "A test imports it" is a weak sense of tested: it says the file runs under test, not that anything checks its behaviour. Per-file coverage would be the better measure and was not run (no coverage run of the whole core suite on this box). Decision 4 should use that, not this list.

**Unused exports** (`node scripts/measure-unused-exports.mjs`): 263 exported values have no other production user (61 mentioned nowhere else, 202 used only by tests); 292 exported types likewise. Regex on source text, so it is a list of places to look. Nothing was deleted.

## 4. Findings that are not fixes

- **The plan is wrong about D-b.** v8 section 3 lists "D-b line on `purix status`" as unbuilt. It is built and wired (`cli/commands/status_index_line.ts`, called from `observability.ts`), has a test, and prints "Indexed files: 2 ..." in the probe. Drop it from the open list.
- **The zip does not contain "this round's H3 overlay".** The v8 plan quotes 3,052 core tests including an H3 test; this zip is the merged tree at 2,987. Apply the H3 overlay (regex tripwire test) separately if it is not in your repository.
- **`@purix/core` exports every file** (`"./*"` in its `package.json`). Any internal module is importable from outside once published. That makes a public API snapshot (H4) a decision first: which modules are public? Not started.
- **Database lock:** with another process holding the write lock, a write waits 5 s and then logs `failed to record "confirm_response" event (non-fatal): database is locked`. Reads and `remember` were not blocked in WAL mode. No data loss seen. Wording unchanged. Not exercised: a command whose main write fails on a lock.
- **Existing corruption handling is real and covered** (`probeIntegrity`, move-aside, tests in `store_inspect.test.ts`); I did not change it.
