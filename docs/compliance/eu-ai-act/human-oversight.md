# EU AI Act — Article 14 Human Oversight: what Purix does

## 1. Implementation
- **TrustGate `human_confirm` path:** an edit with model confidence between the reject threshold (`0.35`) and the confirm threshold (`0.75`), or marked contract-changing, requires confirmation from a person (`packages/core/src/cli-io/confirm.ts`). The model's own confidence decides which side of the line a change falls on.
- **Deterministic Override Floors (DOF):** a change touching a file that matches a DOF pattern cannot auto-commit and goes to human confirmation (`packages/core/src/gates/trustgate.ts`, applied in `lifecycle.ts` and the MCP server). It decides which files always need a person; a file not registered to a component is not covered (`docs/EVIDENCE.md`). Path matching ignores case and treats backslashes as separators (`gates/trustgate_floor.test.ts`). It is a floor on edits that go through Purix; it does not stop an agent that writes to a file directly. A direct write by an agent to a file no component governs is still allowed, but it is named: in the hook's stderr, as an `unadopted_write` event, and in `purix check` under "Edits made outside Purix" (`purix check --strict` exits 1 until the file is adopted). A shell command that writes a file is not named, and whether a given agent shows that stderr line to the person was not tested in a real agent.
- **Overrides:** overriding the security gate, the budget guard or the trust gate is done with a flag that names the gate (`--override-security`, `--override-budget`, `--override-trust`; the old single `--override` is refused) and needs a written reason and is logged in the `override_audits` table; `purix audit-log trail` lists the overrides used and says when one could not be matched to a trail entry (`packages/core/src/security/override_audit.ts`). Each override decision is also written into the hash-chained log, so editing or deleting an `override_audits` row is detected by `purix check` (`security/override_in_chain.test.ts`).
- **Approvers (`packages/core/src/security/auth.ts`):** only user names listed in `.purix/authorized_operators.json` (file mode `0600`) may approve gated changes. A name is the operating-system user name, not a cryptographic identity, so a process running as the same user is not told apart from the person (risk R-03).
